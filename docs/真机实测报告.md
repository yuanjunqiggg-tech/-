# 真机实测报告（2026-09-13 15:20 起）

第一次把整条链路在真云手机上跑通。下面是实测拿到的原始结果，
以及**真机才暴露出来的问题** —— 这些问题之前所有假 Prism 测试都测不出来。

设备：`本机一号`（android，`dev_elribseuror12ih7i3zb`）

## 一、跑通了什么

### 1. Prism 引擎自检 —— 成功

```json
{
  "native": { "installed": true, "alive": true, "port": 8080, "pkg": "com.prismtool.box" },
  "bot": { "connected": true, "dimension": "overworld", "is_op": true, "server": "98014267" },
  "port": 8080
}
```

结论：
- 被控端和 Prism 确实装在同一台机器上
- 被控端能通过 `127.0.0.1:8080` 摸到 Prism
- 那时机器人连着服务器 98014267，还是 OP

### 2. Prism 内置 AI 对话 —— 成功，拿到真实回复

```
发：你好，请用一句话介绍你自己

回：我是Prism工具箱的插件开发助手，专门帮助用户编写和修改
    《我的世界》基岩版的Lua插件或词库插件。
```

**这条回复是从云手机里的 Prism 一路传回来的**，不是我们伪造的：

```
外部 AI Agent
  → https MCP (Cloudflare Worker)
    → D1 写 pending 指令
      → 云手机被控端长轮询领走
        → POST 127.0.0.1:8080/api/ai/chat（SSE 流）
          → Prism 内置 AI
        ← 逐块回传 ai_chunk
      ← /device/report
    ← MCP 返回
```

至此「给 AI Agent 一个网址，它就能用上 Prism 内置 AI」这条需求**验证成立**。

## 二、真机才暴露的问题

### ★ 问题 1：设备上线 3 分钟就掉线（已修，v1.2）

**现象**：15:20 设备在线，心跳 3 秒；15:25 再发指令，报
`设备 本机一号 离线（最后心跳 205 秒前）`。

**根因**：长轮询循环跑在 **WebView 的 JS** 里。
云手机锁屏、或切到别的 App 之后，Android 会节流甚至**整个冻住** WebView 的
JS 定时器。前台服务（通知栏）还活着，所以看起来"在跑"，但循环已经停了。

**修法**：把整条循环搬到原生线程 —— 新增 `NativePoller.java`，
跑在 `AgentService` 的后台线程里，不依赖 WebView 是否存活。
WebView 那边的 JS 循环保留（服务端领指令是原子的，两边同时跑不会重复执行）。

顺带加了 `SYSTEM_ALERT_WINDOW`（悬浮窗）—— 和 Prism 自己一样的保活思路。

### ★ 问题 2：`executed` 报假成功（已修）

**现象**：设备离线、指令**压根没执行**，MCP 却返回 `executed: true`。

**根因**：`mcphttp.ts` 里写的是 `executed: env.executed !== false`。
指令没跑时 `env` 是空对象 → `env.executed` 是 `undefined`
→ `undefined !== false` 竟然等于 **true**。

这个 bug 很坑：外部 AI 会以为自己成功操作了游戏，其实什么都没发生，
然后基于假成功继续往下做决策。

**修法**：改成严格判断 `env.executed === true`，并且在失败时给一句人话
`hint`，告诉 AI 下一步该查什么。

### 问题 3：Prism 内置 AI 不是"游戏操作员"（设计层面，需注意）

它是**插件开发助手**（写 Lua 插件、词库），不是游戏操作员。
所以让它"在游戏里说句话"，它不会去调 `send_command_wait_output` ——
结果就是 `executed: false`。

**对策**：
- 要发游戏消息，直接用 `game_call`（`sendCommandWithResp`）或
  `prism_tool` + `send_command_wait_output`，别指望它自己选工具
- 或者给它更硬的任务描述，逼它发起 tool_call

### 问题 4：机器人会自己掉线（Prism 侧，不是我们的）

同一个 `/api/bot/status`：

| 时间 | connected |
|---|---|
| 15:22 | `true` |
| 15:42 | `false` |

服务器号还是 98014267、`is_op` 还是 true，但 `connected` 变 false ——
机器人在游戏里断开了。这是 Prism 自己的连接管理，需要在 Prism 里重连。

## 三、现在卡在哪

**发游戏消息发不出去**，因为 `connected: false`。

链路本身没有任何问题（Prism AI 的回复就是证据）。
需要做的只是在 Prism 里把机器人重新连上。

连上之后这条命令就能通：

```
prism_tool(
  tool_name = "game_call",
  arguments = { function: "sendCommandWithResp",
                args: ["/say 你好，我是远程 AI"] }
)
```
