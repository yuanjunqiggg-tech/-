# 端到端联调修复记录（2026-09-13）

本轮通过真实链路联调（控制端 → 本地 Worker → 被控端 Agent → 真实 Prism）
发现并修复了 7 个真实缺陷，回归测试 33/33 通过。

## 修复清单

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| 1 | `/health` 返回 401 | 健康检查被 checkAuth 拦截，探针无法免鉴权探测 | 在 checkAuth 之前分流，并补充 `/api/v1/health` 前缀路径 |
| 2 | 抓包数据不落库 | `deviceReport` 只解析 events 里 `type='packet'`，忽略顶层 `packets[]` | 兼容两个来源，字段名做多层兜底（packet_type/type、size/raw_hex 推算） |
| 3 | 指令完成但 result=null | events 里的 `{type:'done'}` 被误判为指令收尾信号，导致中间批次提前终结指令；真正带 result 的那次 report 被 `status IN ('pending','taken')` 拒绝 | 收尾只认显式 `b.done` / `b.error`；被控端把 Prism 的 `ai_done` 映射为 `ai_round_done` 以示区分 |
| 4 | 刚注册设备显示「在线」 | `last_seen` 初始化成 now，注册握手被当成心跳 | 首次注册 `last_seen = 0`，收到首次心跳后才算在线 |
| 5 | agent 拼接出 `/api/v1/api/v1/...` | `--gateway` 传入带 `/api/v1` 后缀的地址，`cloud()` 又拼了一次 | 新增 `_normalize_gateway()` 归一化，容错用户粘贴完整地址 |
| 6 | `cloud() got an unexpected keyword argument 'headers'` | `cloud()` 函数签名缺 headers 参数，心跳/轮询/上报全部抛异常 | 补上 headers 并透传给 http() |
| 7 | report 报 502 Bad Gateway | 系统代理（127.0.0.1:61543）劫持本机请求；`NO_PROXY` 环境变量与 `ProxyHandler` 子类覆写均无效 | `_cloud_opener` 默认直连；需要代理时显式设 `PRISM_USE_SYSTEM_PROXY=1` |

## 关键教训

**代理劫持**：Windows + 系统代理环境下，`urllib.request.build_opener()` 会把
`127.0.0.1` / 局域网请求也丢给代理，报 `Tunnel connection failed: 502`。
两种常见的「修法」都无效：
- 设 `NO_PROXY` 环境变量 —— urllib 的 `ProxyHandler` 默认实例不读它；
- 子类化 `ProxyHandler` 覆写 `proxy_open` 返回 `None` —— 返回 None 的语义是
  「本 handler 不处理」，urllib 仍会继续走代理。
唯一稳妥做法是 `ProxyHandler({})` 彻底直连。

**接口契约漂移**：控制台发 `payload.tool`/`payload.input`，被控端读
`payload.tool_name`/`payload.arguments`，字段名不一致导致工具名传成 `None`。
现已双向兼容，并规定以 `tool_name`/`arguments` 为准。

**SSE 尾部丢事件**：按 256 字节分块读 SSE，最后一块常缺少 `\n\n` 结尾，
导致 `ai_tool_done` 被静默丢弃。改为 4096 字节分块 + 流结束后处理残余 buffer。
