# 多设备远程控制 · 部署与使用

把 Prism 工具箱的「AI 帮写」暴露到公网，用手机/电脑远程操控跑在**云手机**上的它。

---

## 一、整体架构

```
┌──────────────┐         ┌─────────────────────┐        ┌──────────────────┐
│  控制端       │         │  云端（Cloudflare）  │        │  被控端           │
│  手机/电脑    │         │                     │        │  云手机           │
│              │         │  Workers + D1       │        │                  │
│  网页控制台   │──HTTPS─►│  · 鉴权             │◄─主动──│  Prism 被控端App │
│  或 APK      │         │  · 指令队列          │ 外连   │  · 长轮询领指令   │
│              │◄─轮询───│  · 事件流 / 抓包库    │───────►│  · 执行 → 本机Prism│
└──────────────┘         └─────────────────────┘        └──────────────────┘
                                                              │
                                                              ▼
                                                        Prism :8080
                                                        （AI 帮写）
```

**关键设计**：被控端**主动外连**云端领指令，不需要在云手机上装隧道二进制。
这解决了云手机不给 root、不给装 Go 程序的问题。

---

## 二、通信流程

```
① 被控端启动 → POST /api/v1/device/register  → 拿到 device_id + token
② 每 20 秒   → POST /api/v1/device/heartbeat → 上报在线/电量/Prism状态
③ 长轮询     → POST /api/v1/device/poll      → 挂起 25 秒等指令
④ 控制端下发 → POST /api/v1/devices/:id/command → 指令入库
⑤ 被控端领到 → 在自己机器上执行（调本机 Prism :8080）
⑥ 执行过程   → POST /api/v1/device/report    → 分片上报（文本/工具/数据包）
⑦ 控制端拉取 → GET /api/v1/devices/:id/stream?since=N → 游标增量
```

## 三、部署步骤

### 步骤 1 · 建表

```bash
cd workers
npm install

# 设备相关表（第二批）
npx wrangler d1 execute ds-platform --remote --file=../sql/schema_devices.sql

# 如果第一批（提示词/会话表）还没建
npx wrangler d1 execute ds-platform --remote --file=../sql/schema.sql
```

### 步骤 2 · 设置密钥

```bash
# 生成一个强密钥
openssl rand -hex 32
# 例：7f3a9b2c8d1e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0

npx wrangler secret put PLATFORM_ACCESS_KEY
# 粘贴上面的值，回车
```

**这个密钥要记住**——控制端和被控端都要填它。

### 步骤 3 · 部署 Workers

```bash
npx wrangler deploy
```

看到这样的输出就成功了：
```
✨ Deployed ds-platform-ai-assist triggers
  https://ai-api.youyuanqi.dpdns.org
```

### 步骤 4 · 验证

```bash
# 健康检查（不需要密钥）
curl https://ai-api.youyuanqi.dpdns.org/health

# 需要密钥的接口
curl -H "Authorization: Bearer <你的密钥>" \
     https://ai-api.youyuanqi.dpdns.org/api/v1/devices
# 应返回 {"ok":true,"data":{"devices":[],"counts":{...}}}
```

### 步骤 5 · 部署控制台网页

```bash
cd workers
npx wrangler pages deploy ../web --project-name=prism-console
```

部署后在浏览器打开 `https://prism-console.pages.dev/console.html`。

**或者**：直接把 `web/console.html` 用浏览器打开也行（它是单文件零依赖的）。

## 四、在云手机上装被控端

### 方式 A · 直接跑 Python 版（Termux / 有 shell 的环境）

```bash
# 1. 把 agent/prism_agent.py 传到云手机
# 2. 确保云手机上 Prism 工具箱已启动（记下端口，通常 8080）
# 3. 运行

export PRISM_GATEWAY="https://ai-api.youyuanqi.dpdns.org"
export PRISM_URL="http://127.0.0.1:8080"
python prism_agent.py --name "云手机1号"
```

第一次运行会打印：
```
========================================================
  注册成功！
  device_id : dev_xxxxxxxxxxxxxxxx
  token     : dtk_xxxx…（已存到 agent_state.json）
========================================================
```

之后它会自动进入主循环：每 20 秒心跳、长轮询领指令。

### 方式 B · 装 APK（推荐，能常驻后台）

见 **[被控端构建说明.md](./被控端构建说明.md)**。

核心是这三个保活配置，缺一不可：
1. **前台服务** —— `AgentService` 常驻通知栏
2. **开机自启** —— `BootReceiver`
3. **系统设置** —— 关闭电池优化 + 允许自启动 + 云手机平台的后台保活开关

## 五、使用

### 控制台操作

打开控制台 → 填网关和密钥 → 看到设备列表。

**设备列表**显示每台云手机：
- 在线 / 离线
- Prism 是否在跑
- 机器人是否连服
- 电量

**选中设备**后有四个页签：

| 页签 | 作用 |
|------|------|
| **对话** | 像 ChatGPT 一样下指令，实时看 AI 流式回复和工具调用 |
| **抓包** | 实时订阅 + 历史回看数据包 |
| **工具** | 直接调某个 Prism 工具，填 JSON 参数 |
| **信息** | 设备详情、改名字备注、停用/删除 |

### 典型用法

**写插件**
> 在「对话」页输入：写一个玩家进服自动播报欢迎语的插件，用 title 显示

AI 会调用 `write_plugin_file` 直接写进云手机上的 Prism 插件文件。

**抓包分析**
> 切到「抓包」页，填时长 20 秒，点「开始订阅」，
> 然后去游戏里走两步 —— 走完后点「查询历史」，能看到刚才产生的所有包。

**协议调试**
> 在「工具」页填 `list_packet_schema`，参数 `{"packet_type":"PlayerAuthInput"}`，
> 能看到这个包的完整字段定义。

## 六、API 速查

### 被控端 API（用设备 token）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/device/register` | 注册 / 重新绑定 |
| POST | `/api/v1/device/heartbeat` | 心跳 |
| POST | `/api/v1/device/poll` | 长轮询领指令（挂起最长 27s） |
| POST | `/api/v1/device/report` | 上报事件 / 结果 |

请求头：`X-Device-Id`、`X-Device-Token`

### 控制端 API（用管理密钥）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/devices` | 设备列表 |
| GET | `/api/v1/devices/overview` | 全局概览 |
| GET | `/api/v1/devices/:id` | 设备详情 |
| PATCH | `/api/v1/devices/:id` | 改名字/备注 |
| DELETE | `/api/v1/devices/:id` | 停用（`?hard=1` 彻底删除） |
| POST | `/api/v1/devices/:id/command` | 下发指令 |
| GET | `/api/v1/devices/:id/command/:cmdId` | 查指令状态 |
| GET | `/api/v1/devices/:id/stream?since=N` | 事件流（游标增量） |
| GET | `/api/v1/devices/:id/packets` | 抓包历史 |
| GET | `/api/v1/devices/:id/sessions` | 会话列表 |

请求头：`Authorization: Bearer <管理密钥>`

### 指令类型

```jsonc
// 对话
{"kind":"chat","payload":{"message":"写个签到的插件"}}

// 调工具
{"kind":"tool","payload":{"tool_name":"list_packets","arguments":{}}}

// 抓包订阅
{"kind":"packet_sub","payload":{"duration":20,"packet_type":"PlayerAuthInput"}}

// 发包
{"kind":"packet_send","payload":{"packet_type":"RequestChunkRadius","data":{"chunk_radius":12}}}

// 直连 Prism REST
{"kind":"prism_rest","payload":{"path":"/api/bot/status","method":"GET"}}
```

## 七、免费额度评估

Cloudflare 免费版限制（每天）：

| 资源 | 免费额度 | 本方案消耗 |
|------|---------|-----------|
| Workers 请求 | 100,000 次 | 长轮询 25s/次 → 每台设备约 3,456 次/天 |
| D1 读行 | 5,000,000 行 | 每台设备约 20,000 行/天 |
| D1 写行 | 100,000 行 | 心跳 + 事件，每台约 5,000 行/天 |

**结论**：免费额度足够支撑 **20+ 台设备** 同时在线。长轮询是主要开销，如果设备更多可以调大 `POLL_WAIT`。

## 八、安全说明

1. **管理密钥**（`PLATFORM_ACCESS_KEY`）等于整个平台的钥匙，别泄漏
2. **设备 token** 由服务端随机生成，一台一密，泄漏了只影响那台设备
3. 所有设备凭据用**恒定时间比较**，防时序攻击
4. 建议在 Cloudflare 面板给网关加 **Access 策略**（限 IP / 邮箱验证）
5. 抓包数据可能含敏感信息（玩家名、聊天内容），D1 里存的是明文，注意合规

## 九、排查

**设备不出现**
```bash
# 1. 网关通不通
curl https://ai-api.youyuanqi.dpdns.org/health

# 2. 密钥对不对
curl -H "Authorization: Bearer <密钥>" \
     https://ai-api.youyuanqi.dpdns.org/api/v1/devices
```

**设备一直离线**
- 被控端 App 被系统杀了 → 检查前台服务、电池优化、自启动
- 看被控端 App 里的日志有没有报错

**Prism 显示未运行**
- 云手机上 Prism 没启动
- 端口填错了（去 Prism 界面看实际端口）

**下发指令提示「设备离线」**
- 指令会**排队**，等设备上线后自动执行
- 想立刻执行就先去云手机把被控端拉起来

**抓不到数据包**
- 机器人必须先连上服务器。在设备「信息」页看「机器人已连服」
- 未连服时 `wait_packet` 会直接返回错误
