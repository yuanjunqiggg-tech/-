# Prism 工具箱 · 词库插件开发文档

词库（wordbank）插件是插件的一种类型（`type = "wordbank"`）。它给玩家一份「聊天菜单 → 自动执行」的指令菜单：玩家在游戏里发一个触发词，机器人就按你设计的菜单一步步走——发指令、展开子菜单、或先判断再走不同分支。

词库插件**不需要写代码**，用 Web 界面里**图形化点选**就能搭出来。

---

## 一、词库文件在哪

词库插件在 `插件文件/<id>/` 目录下是一个文件，叫 `<id>词库.json`。它和 Lua 插件一样，也有可选的 `manifest.json`（里面 `type` 写 `wordbank`）和 `docs.md`。

你可以在应用里点「插件管理 → 创建 → 词库插件」，会自动生成空词库并进入编辑界面。

---

## 二、怎么编辑词库（图形化）

打开词库插件后，编辑界面默认是**图形化卡片树**，不用碰 JSON：

- **根菜单**一张大卡片，选项一张张小卡片，子菜单自动缩进嵌套。
- 点卡片上的「▸」展开/收起，点「编辑」改这张卡片，点「＋子项」在它下面加子选项，点「删除」去掉。
- 每个选项都能设：**说明**（玩家看到的名字）、**触发词**（玩家发哪个词触发，可多个）、**功能简介**、**仅OP可用**、**参数**（玩家触发时可带的输入）、**动作**（三选一，见下）。
- 编辑完点「保存」，机器人立即生效。

界面右上还有「源码」页签，能看到/手改生成的 JSON（高级玩家才需要，平时不用碰）。

---

## 三、一个选项的「动作」有三种

| 动作 | 意思 | 例 |
|------|------|-----|
| **执行指令** | 触发后发一条或多条游戏指令 | 玩家点「传送」，机器人发 `tp 玩家 0 100 0` |
| **子菜单** | 再展开一层选项（想套几层都行） | 点「发东西」→ 再给「发钻石/发铁锭」等 |
| **判断** | 先判断，满足条件走「成功」分支，不满足走「失败」分支；分支里还能再放指令/子菜单/判断 | 「查玩家」→ 玩家是 OP 就执行成功指令，否则提示没权限 |

判断节点还可以填「成功提示」「失败提示」，判断后直接发给玩家一句提示。

---

## 四、判断条件（5 种）

| 条件 | 意思 | 需要填什么 |
|------|------|-----------|
| 是否OP | 触发者是不是管理员 | 不用填 |
| 是否名单内 | 触发者是不是名单里的人（比如服主） | 名单：每行一个玩家名 |
| 数值范围 | 玩家输入的第几个参数在不在范围内 | 参数序号 + 最小值 + 最大值（可空） |
| 目标是否在线 | 指定的目标玩家在不在服务器 | 目标（支持 `[玩家名]` `[参数:N]`） |
| 服务器数值 | 用一条命令查个数字，和设定值比 | 命令 + 操作符(`>`/`>=`/`<`/`<=`/`==`/`!=`) + 比较值 |

例子：「服务器数值」判断积分够不够 —— 命令填 `scoreboard players get [玩家名] 积分`，操作符 `>=`，比较值 `100`。机器人会执行这条命令，取返回结果里的数字和 100 比。

---

## 五、指令占位符

指令里支持两个占位符，执行前替换成真实值：

- `[玩家名]` —— 触发这条指令的玩家。
- `[参数:N]` —— 玩家带的第 N 个参数（N 从 1 起），按你设的参数顺序对应。

例：玩家发 `发钱 小明 1000`（触发词「发钱」，参数：目标玩家 + 数量），指令 `give [参数:1] diamond [参数:2]` 会变成 `give 小明 diamond 1000`。

玩家没带某个参数时：有默认值用默认值；没有默认值，机器人会在聊天里**问你**，输入「取消」可中止。

---

## 六、游戏里玩家怎么用

1. 玩家发根菜单的触发词（比如「菜单」）。
2. 机器人发选项列表：`1. 传送  2. 发东西  3. 查玩家`。
3. 玩家发编号（`1`、`1.`、`1、`都行）**或直接发触发词**（带参数也行）。
4. 是子菜单就继续列下一层；是指令就执行；是判断就判定后走分支。
5. 随时发「退出」退出菜单；1 分钟没操作自动关闭。

「仅OP可用」的选项，非 OP 玩家**看不到**也**触发不了**。

---

## 七、旧格式兼容

之前用老格式写的词库（只有「触发词 + 指令」，没有动作/菜单）**不用改，照常能用**——会自动识别为「执行指令」。打开编辑器也会显示成卡片树，可以继续升级。

---

## 八、附录：JSON 结构参考（高级玩家）

图形化界面自动生成的就是这个结构。想手写或从别人那儿拿模板时对照看：

```json
{
  "菜单项": [
    {
      "说明": "指令菜单",
      "触发词": ["菜单"],
      "功能简介": "主菜单",
      "仅OP可用": false,
      "参数": [ { "参数名": "数量", "类型": "int", "默认值": 64 } ],
      "动作": {
        "类型": "子菜单",
        "子菜单": [
          { "说明": "传送", "触发词": ["传送"],
            "动作": { "类型": "指令", "指令": ["tp [玩家名] 0 100 0"] } },
          { "说明": "查积分", "触发词": ["查"],
            "动作": {
              "类型": "判断",
              "判断": {
                "条件": { "类型": "服务器数值", "命令": "scoreboard players get [玩家名] 积分", "操作符": ">=", "比较值": 100 },
                "成功": { "类型": "指令", "指令": ["say 达标"] },
                "失败": { "类型": "指令", "指令": ["say 积分不够"] }
              }
            } }
        ]
      }
    }
  ]
}
```

- `动作.类型`：`指令` / `子菜单` / `判断` 三种之一。
- `判断.条件.类型`：`是否OP` / `是否名单内` / `数值范围` / `目标在线` / `服务器数值`。
- `参数.默认值`：填 `null` 表示必填；填了数字/文字则玩家没带时用它。
- 需要复杂逻辑（循环、定时、跨插件调用等）时，请用 Lua 插件类型。
